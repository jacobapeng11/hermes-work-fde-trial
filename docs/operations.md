# 客户试用操作指南

## 用户工作台

1. 打开客户部署的 HTTPS 地址，经 OAuth2 登录。首次进入任务页时，平台按账号准备个人 Runtime；如尚未 Ready，等待页面提示完成。
2. 在「任务」输入目标，选择已授权模型并发送。可上传任务文件；任务运行中可查看流式进度、取消或在断线后恢复。
3. 任务生成的文件显示在右侧文件区。下载前确认文件内容符合客户自己的数据管理规则。
4. 「看板区」可预览和管理已生成的 HTML 看板，并按权限分享。
5. 「专家与技能」可创建个人专家、选择授权能力并安装公开市场能力；公开市场内容由管理员治理。
6. 「知识库」用于个人知识文件与授权管理；企业知识语义查询需客户另行接入业务数据服务。
7. 「定时任务」仅在模型、Runtime 与相应权限已配置后启用。

## 桌面端

安装客户针对自己环境构建的桌面包。登录后界面与用户 Web 主流程一致。使用「本地路径」选择当前任务工作目录；本地文件能力只作用于用户授权的目录。关闭桌面窗口不等于取消已经提交的云端 Run，重新打开后可查看任务状态。

## 管理控制台

使用具备平台管理权限的账号访问 `/admin/`。建议按以下顺序完成试用配置：

1. 检查资源视图中的 Node、Pod、Runtime Ready 与容量。
2. 配置模型 Provider、API Key、模型能力与可见范围，发布后用普通用户账号验证可见性和调用。
3. 配置组织与角色权限，再发布专家、技能或应用 Agent 资产。
4. 如启用个人知识或外部 MCP，先配置客户自己的服务地址与凭据并做最小范围试验。
5. 查看用量、审计日志和 Runtime 状态，确认权限和调用符合预期。

## 日常维护

- 只改 Backend/Web：构建静态 Web 后执行 `bash scripts/restart-public.sh prod`。该入口不切换 Runtime 镜像。
- 改 Supervisor、Runtime 插件/依赖/Skill：先阅读 `scripts/README.md` 与目标脚本，确认全局冻结、旧 Pod 归零、PVC 单写、KService reset、live imageID 门禁，再执行完整镜像构建/切换。
- 备份：分别备份 Backend MySQL、Supervisor SQLite 所在 Runtime PVC 与 Hermes `state.db`；仅备份其中一处不能恢复完整会话。
- 故障排查：用 `session_id`、`run_id`、`runtime_id`、`binding_id` 和事件 `seq` 串联日志，不在工单中粘贴 Token、用户正文或 `.env`。

试用环境也应按客户策略执行访问控制、密钥轮换、数据留存和备份。生产上线前应补齐容量、故障恢复、权限与 TTFT 真实验收。
